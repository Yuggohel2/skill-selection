# Example: Production SaaS Application

This is a sample manifest generated by `/skill-selection` for a production
SaaS dashboard with a multi-tenant backend and CI/CD pipeline.

## Context

- **Project:** Multi-tenant analytics SaaS dashboard
- **Stack:** React + TypeScript + Tailwind + PostgreSQL + Docker
- **Context:** Production application — reliability and code quality matter
- **Team:** 3 developers, shared codebase with conventions

## Key Differences from Hackathon Manifest

Notice how the same skill (`ponytail`) is **active** in a hackathon but
**suppressed** in production. And `test-driven-development` is **suppressed**
in a hackathon but **active** in production.

The classification is the same — both are PROJECT skills. The **selection**
changes based on the plan's context. This is why skill-selection is dynamic,
not a static config.

| Skill | Hackathon | Production |
|-------|:---------:|:----------:|
| ponytail | Active | Suppressed |
| test-driven-development | Suppressed | Active |
| verification-before-completion | Suppressed | Active |
| ui-ux-pro-max | Active | Active |
| slides | Suppressed | Suppressed |
